# Highlight groups reference

Every highlight group this Neovim config can hit: builtin (Vim-inherited + Neovim's own),
Neovim LSP, Tree-sitter, and every plugin in `config.nix`. Format is `Group` (standalone) or
`Group -> Target` (default link). Generated by statically reading the doc/source of the exact
plugin versions pinned in `flake.lock` (via their Nix store paths), not by probing a running
`nvim` — several of these families (Vim's per-filetype syntax files, VimTeX's per-package
files, nvim-web-devicons' per-icon table, nvim-notify's per-buffer groups) only materialize
their groups lazily/dynamically, so those are documented as *patterns* instead of exhaustive
instances. Verified against nvim 0.12.4 runtime docs and the plugin versions currently in the
Nix store.

## 10. lualine.nvim (`lua/lualine/highlight.lua`)

No fixed group names — it generates `lualine_<section>_<mode>` for every section actually
configured. This config's `scripts/lualine_theme.lua` configures sections `a b c x y z` (via
`winbar`/`inactive_winbar` too) across every mode, so the live set is:

```
lualine_{a,b,c,x,y,z}_{normal,insert,visual,replace,command,terminal,inactive}
```
e.g. `lualine_a_normal`, `lualine_c_insert`, `lualine_x_inactive`, ... (42 groups total).
`scripts/breadcrumbs.lua` (used as a winbar component) reads colors back out of these via
`require("lualine.highlight")` rather than defining new ones.

runs — and only then defines its `tex<Cmd>{Opt,Arg,...}` groups via
`vimtex#syntax#core#new_cmd()` — when the current document actually `\usepackage{}`s that
package. Not enumerable without opening documents that exercise each one, so intentionally
left as a pattern rather than a static list here.

## 18. nvim-web-devicons

One group per filetype/icon entry, named `DevIcon<Name>` (e.g. `DevIconLua`, `DevIconC`,
`DevIconDefault`) — hundreds of entries generated from its internal icon table, not a fixed
list. Consumed by nvim-tree and diffview for file icons.

## 19. Plugins with no highlight groups

`vim-clang-format`, `hologram.nvim`, `neodev.nvim`, `vim-devicons` (superseded here by
nvim-web-devicons), and the local `coc-nav` package define none — `coc-nav` only reuses the
`CocSymbol*` icons from §8 and fires a `CocNavChanged` autocommand (not a highlight group).
